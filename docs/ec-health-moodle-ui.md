# Eastern Cape Health Moodle UI

## Theme decision

This checkout is Moodle 5.3+ (Build 20261021). Use the bundled Boost theme through the existing `theme_echealth` child theme. Boost is included with Moodle and therefore matches this checkout. The existing theme supplies the Eastern Cape logo, multicolour government-inspired strip, palette, dashboard graphics, responsive course thumbnails, and capability-aware desktop/mobile navigation.

Edwiser RemUI was not selected: its published product page currently describes Moodle compatibility through 5.1, and its commercial download/license is not available in this checkout ([Edwiser RemUI](https://edwiser.org/remui-moodle-theme)). Boost Union was not selected: the Moodle Plugins directory lists its newest release for Moodle 5.0 ([Boost Union versions](https://moodle.org/plugins/theme_boost_union/versions)). Neither release is compatible evidence for this 5.3+ build. Recheck the vendors' compatibility and license terms before reconsidering either option.

The existing theme is preserved as the working rollback implementation. A point-in-time archive is available at `backups/echealth-theme-rollback-2026-10-27.zip`.

## Branding and assets

The `theme_echealth` renderer serves the configured logo from Moodle's system-context theme file area, with `pix/ec-health-logo.png` as its fallback. The government strip, hero graphic, course placeholder, course thumbnails, and SVG icons live under `public/theme/echealth/pix/` and are referenced by the child theme's templates and SCSS. Keep these files in the plugin so their URLs are generated by Moodle and remain cache/deployment safe. Purge Moodle caches after changing theme settings or assets.

If graphics are missing in a running site, check that `echealth` is installed and selected, that theme caches have been purged, and that the page uses the expected template/layout. The source checkout alone cannot establish the active database theme setting or the runtime file serving configuration.

## Portal listings

`public/local/echealthnav/index.php` uses Boost's `report` page layout for custom management views. Both `standard` and `report` use Boost's native drawers layout, but the desktop 830px content cap is scoped to `pagelayout-standard` / `body.limitedwidth`; the `report` layout avoids that reading-width constraint while keeping Moodle's navigation, block region, and page header. The page adds one `ec-management-page` body class for reusable toolbar, intro, table, and course-card styling in the theme.

The shared page introduction is `public/local/echealthnav/templates/page_intro.mustache`. The activity course picker is `course_selector_card.mustache`. Create Exam and Create Assignment search through Moodle's `get_courses_search()` with the appropriate `mod/*:addinstance` capability filter and page limit, and support category filtering, results counts, page size, and Moodle pagination. Continuing posts a Moodle session key; the server rechecks the activity capability before redirecting to `/course/modedit.php`. Quiz configuration and question creation remain native Moodle flows.

Other listing views provide shared search, course/status filters, sorting, page-size selection, result counts, and Moodle pagination. Their activity and learner rows are still assembled from the courses and activities visible to the logged-in user, then filtered and paginated in the request. For very large installations, move these listings to paged database queries / Moodle table APIs rather than loading every authorized row before slicing the result. Capability checks remain in place before showing course, learner, report, or activity destinations.

## Source-tree plugin inventory

Core activity plugins present in `public/mod/` include Assign, Quiz, Attendance, Custom certificate, Forum, Choice, Feedback, Lesson, Workshop, H5P activity, Book, Page, Resource, and other bundled Moodle activities. `public/theme/echealth/` and `public/local/echealthnav/` are local custom plugins. Attendance and Custom certificate have source directories in this checkout but are untracked files; their presence here does not prove that they are installed or enabled in the site's database. Moodle's Plugins overview is the authoritative installed/enabled inventory.

## Validation and maintenance

This source checkout has no PHP executable and no accessible Moodle runtime/database. Therefore theme activation, login roles, activity creation/grading, enrolment, responsive screenshots, cache behavior, and plugin installation state must be verified in the configured Moodle site. On that site, test with student, lecturer, and administrator accounts; check empty and populated views, the filter/paging controls, native course navigation, keyboard focus, narrow screens, and the configured logo and graphics. After deployment, purge caches and use Moodle's Plugins overview to confirm compatibility and installed status.
